## How it works

Containers versus VMs, images, layers, users, networks and volumes.

An image packages application/runtime inputs; a container is a process using that image. Writable runtime state belongs in an explicit persistent location. A recreated container may otherwise lose data even when its image remains available. Build once, inspect the image identity, and use a non-root runtime identity with a writable data volume.
