# 03. Compose a small service

Run edge, application and state components with explicit data locations.

Author estimate: 90 minutes guided practice and 120 minutes independent work; split into sessions as needed. The portable preparation alone is usually 5–15 minutes. Setup, downloads and provider approval are separate.

## Before starting

Portable model: Python 3.11+ and an editor. Native operation: Docker with Compose v2, the preceding ascend-relay:lab image and a dedicated project/data volume.

Download /training/io-delivery-automation.zip and extract it into a NEW folder you choose on your PC. Open a terminal in its io-delivery-automation directory; read README.md and bootstrap.md. Python 3.11+ runs the portable tools without extra Python packages. POSIX examples use Linux; Windows users can use a prepared Linux guest or WSL for the initial shell practice. Create work/ and notes/. Copy notes-template.md in your editor to notes/03.md, or append a dated attempt if the note already exists. Input files are in inputs/NN/, portable starting cases in cases/, operational instructions in lessons/NN.md, and the shared synthetic service in shared/. All generated work remains in the local paths printed by the tools. Opening a challenge does not create or upload these files. Use Ascend's notebook/upload control only when you choose to copy evidence into Ascend. Run commands one at a time on the named HOST, GUEST or CLIENT. Replace explicit address/key placeholders after inspection, and keep each foreground service in its own terminal. Stop its process with Ctrl+C before reusing the same listener.

Use only the named learner-owned environment. Commands that install packages or change services, networks, storage or VMs belong on that specified guest/host. A college-provided guest account is not permission to administer the physical host.

## How it works

Compose, dependencies, readiness, secrets, logs and owned cleanup.

Compose declares several related runtime resources and their ownership. Startup order is not application readiness; checks must observe the endpoint and required dependencies. Named volumes, networks and project names determine what cleanup removes. Review the fully rendered configuration before starting it.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
docker compose -p ascend-infra -f inputs/03/compose.yaml config
docker compose -p ascend-infra -f inputs/03/compose.yaml up -d
docker compose -p ascend-infra -f inputs/03/compose.yaml ps
docker compose -p ascend-infra -f inputs/03/compose.yaml logs --tail 30
python3 shared/check_service.py --url http://127.0.0.1:8088 --expect-release container-v1 --write
docker compose -p ascend-infra -f inputs/03/compose.yaml down
# The default down retains the named data volume; inspect before intentionally deleting it.
```
