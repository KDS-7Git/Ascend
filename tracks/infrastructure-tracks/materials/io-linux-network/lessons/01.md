## How it works

Processes, sockets, client/server, addresses and ports.

A URL names a protocol, host and optional port. The operating system delivers a TCP connection to a listening socket owned by a process; that process interprets HTTP. A DNS answer or a listening socket proves only one part of the path. Follow one request before changing configuration, and distinguish an HTTP error from failure to connect.
