## How it works

Stub/recursive/authoritative DNS, records, TTL, cache and split DNS.

A hosts-file substitution, recursive resolver response and authoritative DNS response are different observations. DNS TTL affects caching; changing an application does not repair a wrong A/AAAA record. A bad IPv6 answer can break some clients even when IPv4 works. Use an explicit resolver or curl address override to isolate DNS without claiming the override repaired public DNS.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
dig example.com A
dig example.com AAAA
dig example.com NS
# Record answer source and TTL, not only the IP address.
curl --resolve relay.test:8000:127.0.0.1 http://relay.test:8000/version
# The --resolve command needs the local Relay process and affects this curl invocation only.
```

### Operation 2

```sh
# Optional isolated DNS GUEST, after installing dnsmasq in that disposable guest.
dnsmasq --no-daemon --port=1053 --listen-address=127.0.0.1 --bind-interfaces --no-hosts --no-resolv --address=/relay.test/127.0.0.1
# Second terminal: dig @127.0.0.1 -p 1053 relay.test A
```
