# 08. Recover your first service

Follow a worked service outage, then build a small request-path runbook.

Author estimate: 90 minutes guided practice and 120 minutes independent work; split into sessions as needed. The portable preparation alone is usually 5–15 minutes. Setup, downloads and provider approval are separate.

## Before starting

Portable model: Python 3.11+ and an editor. Native operation: Python, curl and ss in your owned Linux environment; retain the service/data from the earlier operations.

Download /training/io-linux-network.zip and extract it into a NEW folder you choose on your PC. Open a terminal in its io-linux-network directory; read README.md and bootstrap.md. Python 3.11+ runs the portable tools without extra Python packages. POSIX examples use Linux; Windows users can use a prepared Linux guest or WSL for the initial shell practice. Create work/ and notes/. Copy notes-template.md in your editor to notes/08.md, or append a dated attempt if the note already exists. Input files are in inputs/NN/, portable starting cases in cases/, operational instructions in lessons/NN.md, and the shared synthetic service in shared/. All generated work remains in the local paths printed by the tools. Opening a challenge does not create or upload these files. Use Ascend's notebook/upload control only when you choose to copy evidence into Ascend. Run commands one at a time on the named HOST, GUEST or CLIENT. Replace explicit address/key placeholders after inspection, and keep each foreground service in its own terminal. Stop its process with Ctrl+C before reusing the same listener.

Use only the named learner-owned environment. Commands that install packages or change services, networks, storage or VMs belong on that specified guest/host. A college-provided guest account is not permission to administer the physical host.

## How it works

Diagnosis, evidence, least-change repair and handover.

A useful incident record starts with observations and a hypothesis, then changes the smallest responsible component and repeats the control. This lab combines DNS, binding and process state. A repaired page must not be obtained by granting unrelated file or network access. Keep a runbook another learner can use without your memory.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
# PC or service GUEST, in this extracted track directory; leave this terminal running.
mkdir -p data
python3 shared/relay.py --host 127.0.0.1 --port 8000 --data data/relay.sqlite --release v1
```

### Operation 2

```sh
# Reproduce the incident by using an intentionally wrong client port.
curl --max-time 2 -i http://127.0.0.1:8999/version
ss -ltnp
curl --max-time 2 -i http://127.0.0.1:8000/version
# Then stop Relay and compare the same request. Restart only your Relay process.
python3 shared/check_service.py --url http://127.0.0.1:8000 --expect-release v1 --write
```
