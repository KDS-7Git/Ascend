## How it works

Postfix, domains, relaying policy, ports, queues and rejection.

An MTA accepts, queues, routes and delivers mail according to domain and relay policy. Local delivery for an owned test domain is different from forwarding arbitrary recipients. Start with a loopback-only MTA in a disposable guest, then a second isolated peer if available. Preserve the refusal of unauthorized relay while enabling the legitimate path.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
# Disposable Ubuntu/Debian MAIL GUEST only; install/configure its Postfix interactively as local lab mail.
sudo apt-get install postfix mailutils
sudo postconf -e 'myhostname = mail.relay.test'
sudo postconf -e 'mydestination = $myhostname, localhost.$mydomain, localhost, relay.test'
sudo postconf -e 'inet_interfaces = loopback-only'
sudo postconf -e 'mynetworks = 127.0.0.1/32 [::1]/128'
sudo postconf -e 'smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination'
sudo postfix check
sudo systemctl restart postfix
postconf -n
printf 'Synthetic local mail
' | mail -s 'Relay lab' "$USER"
postqueue -p
# To add a second owned guest, declare only its explicit lab address and test relay rejection from an untrusted peer.
```
