## How it works

Dovecot/IMAP, submission, TLS, credentials, mailbox storage and service roles.

SMTP submission authenticates a sender to an MTA; IMAP provides mailbox access. These are distinct endpoints with separate TLS and authorization requirements. Use a disposable guest and a synthetic local account. Verify the installed Dovecot version before applying configuration: the supplied teaching fragment uses the Dovecot 2.3 syntax common on Ubuntu 24.04.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
# Disposable MAIL GUEST with the preceding local Postfix exercise configured.
sudo apt-get install dovecot-imapd
dovecot --version
# Stop here and use that version's reference if it is not Dovecot 2.3.
sudo useradd --create-home labmail
sudo passwd labmail
mkdir -p work/tls
umask 077
openssl req -x509 -newkey rsa:2048 -nodes -days 1 -keyout work/tls/key.pem -out work/tls/cert.pem -subj /CN=localhost -addext subjectAltName=DNS:localhost
sudo install -m 0644 work/tls/cert.pem /etc/ssl/certs/ascend-mail-lab.pem
sudo install -m 0600 work/tls/key.pem /etc/ssl/private/ascend-mail-lab.key
sudo install -m 0644 inputs/03/dovecot-2.3-lab.conf /etc/dovecot/conf.d/99-ascend-lab.conf
sudo postconf -e 'home_mailbox = Maildir/'
sudo postfix check
sudo doveconf -n
sudo systemctl restart postfix dovecot
printf 'Synthetic message for IMAP
' | mail -s 'Mailbox control' labmail
openssl s_client -connect 127.0.0.1:993 -servername localhost -verify_hostname localhost -verify_return_error -CAfile work/tls/cert.pem -crlf
# In the TLS IMAP session: a1 LOGIN labmail YOUR_SYNTHETIC_PASSWORD
# a2 SELECT INBOX
# a3 FETCH 1 BODY[TEXT]
# a4 LOGOUT
# Repeat with a wrong password; repeat s_client using -verify_hostname wrong.invalid to observe name rejection.
# Next configure the distinct authenticated submission endpoint using the following block.
```

### Operation 2

```sh
# Same disposable Ubuntu MAIL GUEST, after TLS, Maildir, local user and Dovecot work.
# Review existing master.cf, then configure only this guest's loopback submission service.
sudo cp /etc/postfix/master.cf work/master-before-submission.cf
sudo postconf -e 'smtpd_tls_cert_file = /etc/ssl/certs/ascend-mail-lab.pem'
sudo postconf -e 'smtpd_tls_key_file = /etc/ssl/private/ascend-mail-lab.key'
sudo postconf -M 'submission/inet=submission inet n - y - - smtpd'
sudo postconf -P 'submission/inet/smtpd_tls_security_level=encrypt'
sudo postconf -P 'submission/inet/smtpd_sasl_auth_enable=yes'
sudo postconf -P 'submission/inet/smtpd_sasl_type=dovecot'
sudo postconf -P 'submission/inet/smtpd_sasl_path=private/auth'
sudo postconf -P 'submission/inet/smtpd_relay_restrictions=permit_sasl_authenticated,reject'
sudo postconf -P 'submission/inet/smtpd_recipient_restrictions=permit_sasl_authenticated,reject'
sudo postfix check
sudo doveconf -n
sudo systemctl restart postfix dovecot
ss -ltn
# Confirm 587 remains loopback-only (inet_interfaces was set in lesson 2).
python3 inputs/03/submit_authenticated.py
python3 inputs/03/submit_authenticated.py --wrong-password
python3 inputs/03/submit_authenticated.py --unauthenticated
# The script prompts privately for the valid synthetic password and verifies the localhost certificate.
# Open the earlier IMAP session and fetch the accepted message; refused attempts must not appear.
# This proves local authenticated submission/mailbox controls, not external SMTP or public deliverability.
```
