## How it works

MX, SPF, DKIM, DMARC, alignment, signing and verification.

SPF evaluates an envelope domain against a sending IP; DKIM verifies a signature over selected content; DMARC relates authenticated identities to the visible From domain. None is encryption or a guarantee of inbox placement. A local test DNS zone can teach alignment and signing before public delegation exists.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
# Disposable Ubuntu MAIL/DNS GUEST; use its local resolver, never change the shared host's resolver.
# Required packages in that owned guest: opendkim-tools, dnsmasq-base, openssl and dnsutils.
mkdir -p work/dkim
umask 077
opendkim-genkey -b 2048 -d relay.test -s lab -D work/dkim
openssl rsa -in work/dkim/lab.private -pubout -outform DER | openssl base64 -A > work/dkim/lab-public.b64
python3 inputs/04/make_local_dns.py
dnsmasq --test --conf-file=work/dkim/dnsmasq.conf
# Check that no existing guest service owns 127.0.0.1:53 before starting this listener.
sudo dnsmasq --no-daemon --conf-file=work/dkim/dnsmasq.conf
# Leave DNS in Terminal A. In guest Terminal B, inspect its actual interface and resolver:
# ip -br address
# resolvectl status
# Set split DNS for .relay.test on this GUEST's actual interface only:
# sudo resolvectl dns ACTUAL_LAB_INTERFACE 127.0.0.1
# sudo resolvectl domain ACTUAL_LAB_INTERFACE '~relay.test'
# Verify the installed resolver uses that route: dig lab._domainkey.relay.test TXT
# If this guest lacks systemd-resolved, configure its equivalent scoped test resolver explicitly first.
```

### Operation 2

```sh
# Same GUEST after the system resolver actually sees the isolated DKIM TXT record.
dig relay.test MX
dig relay.test TXT
dig _dmarc.relay.test TXT
opendkim-testkey -d relay.test -s lab -k work/dkim/lab.private -vvv
opendkim-testmsg -d relay.test -s lab -k work/dkim/lab.private < inputs/04/message.eml > work/dkim/signed.eml
opendkim-testmsg < work/dkim/signed.eml
# Successful verification exits zero. It may print no output; inspect the exit status.
cp work/dkim/signed.eml work/dkim/tampered.eml
# In your editor change one non-whitespace body word in tampered.eml, leaving the signed headers intact.
opendkim-testmsg < work/dkim/tampered.eml
# The changed body must now fail signature verification. Header parsing alone cannot establish this result.
# Compare the signing d=relay.test with the visible From domain and interpret the published SPF/DMARC fixtures.
# SPF's 192.0.2.10 is an invented documentation input, not this guest's public identity.
```
