## How it works

SSH -R/-D, SOCKS, GatewayPorts, relay reachability and connection lifetime.

A reverse SSH forward creates the listening side on the remote SSH server and connects back through the authenticated session. Dynamic forwarding supplies a SOCKS proxy for supporting clients; it is not a full IP VPN. A reverse connection from a CGNAT origin still needs a reachable relay. GatewayPorts and listener bindings decide who can connect to it.

### Operation 1

```sh
# ORIGIN: Relay listens at its own loopback:8000; RELAY is an owned reachable SSH server.
ssh -N -o ExitOnForwardFailure=yes -R 127.0.0.1:18000:127.0.0.1:8000 learner@ACTUAL_RELAY_ADDRESS
# RELAY console: curl http://127.0.0.1:18000/version
# Separate CLIENT experiment with the owned SSH server:
ssh -N -D 127.0.0.1:1080 learner@ACTUAL_RELAY_ADDRESS
# CLIENT: curl --socks5-hostname 127.0.0.1:1080 http://PRIVATE_SERVICE_FROM_RELAY:8000/version
# Close each forwarding session when finished. Keep management access separate.
```
