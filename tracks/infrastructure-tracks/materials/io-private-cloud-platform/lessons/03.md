## How it works

Projects, memberships, API identities, ownership, quotas and audit records.

Multi-user isolation must be enforced by the management API and daemon. Hiding a button cannot restrict a user who has unrestricted host sockets or certificates. Give each learner a confined project identity, test direct denied API calls and preserve a separate operator recovery identity. Quotas and ownership are separate controls.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
# OPERATOR on that OWNED Incus lab host. Only this host identity retains full administration.
incus project create ascend-b -c features.images=true -c features.profiles=true -c features.networks=false
# Repeat the lab-small profile creation/root/NIC commands from level 2 for --project ascend-b.
incus project set ascend-a restricted=true limits.instances=2 limits.memory=3GiB
incus project set ascend-a restricted.devices.nic=managed restricted.networks.access=incusbr0
incus project set ascend-b restricted=true limits.instances=2 limits.memory=3GiB
incus project set ascend-b restricted.devices.nic=managed restricted.networks.access=incusbr0
incus config trust list
# Enable TLS management only on a chosen PRIVATE host address reachable by the two owned clients.
# Example after replacing ACTUAL_PRIVATE_HOST_ADDRESS: incus config set core.https_address ACTUAL_PRIVATE_HOST_ADDRESS:8443
# Record/verify the server certificate fingerprint through the operator's trusted console.
incus config trust add learner-a --projects ascend-a --restricted
incus config trust add learner-b --projects ascend-b --restricted
# Each command produces a separate enrollment token; deliver to its OWN client and do not submit it as evidence.
# CLIENT A and CLIENT B must be different client configurations/identities with no full host socket access.
# CLIENT A: incus remote add college TOKEN_FOR_A --project ascend-a
# CLIENT B: incus remote add college TOKEN_FOR_B --project ascend-b
# The remote's --project option selects a project; the server's restricted certificate enforces confinement.
```

### Operation 2

```sh
# CLIENT A: use its enrolled restricted remote for all these calls.
incus list college: --project ascend-a
incus info college:relay-a --project ascend-a
# OPERATOR first creates a B-owned relay-b using B's profile/cloud-init as in level 2.
incus info college:relay-b --project ascend-b
incus config set college:relay-b limits.memory=2GiB --project ascend-b
# Those B requests must be denied by the daemon, not merely absent from a UI.
# Repeat A access from CLIENT B and record the denial. A single unrestricted client changing --project is not this test.
# Revoke a learner certificate by its exact recorded fingerprint at cleanup:
# OPERATOR: incus config trust remove ACTUAL_LEARNER_CERTIFICATE_FINGERPRINT
# Confirm that client's subsequent allowed-project request is now denied.
```
