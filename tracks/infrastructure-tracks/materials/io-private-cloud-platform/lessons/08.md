# 08. Run the college-style capstone

Operate two learner guests through the selected existing control plane and hand over a reproducible runbook.

Author estimate: 90 minutes guided practice and 120 minutes independent work; split into sessions as needed. The portable preparation alone is usually 5–15 minutes. Setup, downloads and provider approval are separate.

## Before starting

Owned Linux Incus HOST with KVM, a reviewed Incus version/image server, one supported storage pool and private managed bridge, plus approximately 1 GiB initial guest RAM and 12 GiB sparse guest disk. Keep a separate host reserve. A prepared guest/SSH account alone does not authorize host administration. Multi-user operations also require two distinct restricted TLS clients and the operator recovery identity; native results are required.

Download /training/io-private-cloud-platform.zip and extract it into a NEW folder you choose on your PC. Open a terminal in its io-private-cloud-platform directory; read README.md and bootstrap.md. Python 3.11+ runs the portable tools without extra Python packages. POSIX examples use Linux; Windows users can use a prepared Linux guest or WSL for the initial shell practice. Create work/ and notes/. Copy notes-template.md in your editor to notes/08.md, or append a dated attempt if the note already exists. Input files are in inputs/NN/, portable starting cases in cases/, operational instructions in lessons/NN.md, and the shared synthetic service in shared/. All generated work remains in the local paths printed by the tools. Opening a challenge does not create or upload these files. Use Ascend's notebook/upload control only when you choose to copy evidence into Ascend. Run commands one at a time on the named HOST, GUEST or CLIENT. Replace explicit address/key placeholders after inspection, and keep each foreground service in its own terminal. Stop its process with Ctrl+C before reusing the same listener.

Use only the named learner-owned environment. Commands that install packages or change services, networks, storage or VMs belong on that specified guest/host. A college-provided guest account is not permission to administer the physical host.

## How it works

Template → assigned guest → SSH → hosted site → measured load → resize → recovery → release.

A college-style service joins template selection, project identity, resource admission, guest boot, SSH, application publishing, observation and recovery. Each stage needs its own evidence and permissions. Use the existing platform UI/API to prove the workflow before building a custom front end; retain failed-operation state until inventory is reconciled.
