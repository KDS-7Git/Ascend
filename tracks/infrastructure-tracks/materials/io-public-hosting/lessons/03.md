## How it works

DNS delegation, A/AAAA/CNAME, TTL, ACME, HTTP/DNS challenges and renewal.

DNS delegation establishes who answers for a name; records direct clients but do not open a network path. TLS proves a server name against a trusted issuer. ACME HTTP-01 needs a reachable challenge endpoint; DNS-01 needs authority over the challenge record. Private-CA practice can prove local TLS controls without purchasing a domain, while public issuance remains separately qualified.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
dig example.com NS
dig example.com A
dig example.com AAAA
mkdir -p work/tls
openssl req -x509 -newkey rsa:2048 -nodes -days 1 -keyout work/tls/key.pem -out work/tls/cert.pem -subj /CN=localhost -addext subjectAltName=DNS:localhost
openssl s_server -accept 127.0.0.1:8443 -cert work/tls/cert.pem -key work/tls/key.pem -www
# Second terminal:
# curl --cacert work/tls/cert.pem https://localhost:8443/
# curl --cacert work/tls/cert.pem https://127.0.0.1:8443/  # must reject the name
# For a public domain, use only your authoritative DNS account and inspect A/AAAA and challenge authority first.
```
