## How it works

Sessions, shared state, sticky routing, streaming, WebSockets and retryable writes.

Stateless requests can be sent to either replica, but user sessions and writes require a state ownership and consistency design. Sticky routing can preserve locality while still failing if the selected instance disappears. Retrying a write without an idempotency contract can duplicate work. Observe these application controls rather than assuming a load balancer supplies them.
