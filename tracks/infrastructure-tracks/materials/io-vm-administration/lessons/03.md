## How it works

NAT, bridge, routed networks, virtual switches, DHCP and host/guest firewalls.

A NAT virtual network gives guests a private subnet and an outward path through the host. A bridge connects virtual NICs to a chosen network but does not grant an address or bypass firewalls. Wireless bridging support varies. Use default libvirt NAT first and examine host/guest/edge routes separately; a successful guest boot does not imply reachability.

### Operation 1

```sh
# HOST: inspect the existing default lab network; do not replace the host network.
sudo virsh -c qemu:///system net-list --all
sudo virsh -c qemu:///system net-dumpxml default
sudo virsh -c qemu:///system domiflist relay-a
sudo virsh -c qemu:///system domifaddr relay-a
# GUEST console:
# ip -br address
# ip route
# ss -ltnp
# Choose the observed address when connecting from the HOST/CLIENT.
```

### Operation 2

```sh
# Optional second private network, on the owned libvirt HOST only.
# Check first that 172.29.44.0/24 and ascendbr1 do not conflict with an existing host/VPN route.
ip route
sudo virsh -c qemu:///system net-define inputs/03/isolated-network.xml
sudo virsh -c qemu:///system net-start ascend-isolated
sudo virsh -c qemu:///system net-dumpxml ascend-isolated
# This XML has no <forward> element: it creates an isolated virtual network, not a public LAN bridge.
# Stop relay-a before attaching its extra persistent NIC; keep its original management NIC.
sudo virsh -c qemu:///system shutdown relay-a
sudo virsh -c qemu:///system domstate relay-a
sudo virsh -c qemu:///system attach-interface relay-a network ascend-isolated --model virtio --config
sudo virsh -c qemu:///system domiflist relay-a
sudo virsh -c qemu:///system start relay-a
# GUEST: match the NEW NIC MAC from domiflist to ip link; do not modify the original NIC.
# GUEST: sudo ip link set ACTUAL_NEW_LAB_INTERFACE up
# GUEST: sudo ip address add 172.29.44.10/24 dev ACTUAL_NEW_LAB_INTERFACE
# GUEST: run Relay bound only to 172.29.44.10:8000, then HOST curl http://172.29.44.10:8000/version
# A second learner-owned client guest can use 172.29.44.11/24 on this same network.
# Inspect both routes and test wrong-address/bind failures without granting unrelated ports.
# At cleanup stop each involved guest, detach only this added NIC by its recorded MAC,
# then stop/undefine ascend-isolated only after confirming no other guest uses it.
# This extra interface does not remove an existing default route on the original guest NIC.
```
