## How it works

Configured/current resources, quotas, balloon/hotplug support, virtual disk versus filesystem.

Virtual CPU count, scheduler quota and actual CPU time are different controls. Configured memory may require a reboot, balloon support or guest hotplug support before it changes. Disk capacity exists at multiple layers: virtual block device, partition, volume and filesystem. Back up the owned guest before changing storage and inspect each layer after the change.

### Operation 2

```sh
# HOST; stop only your owned guest and wait until domstate reports shut off.
sudo virsh -c qemu:///system shutdown relay-a
sudo virsh -c qemu:///system domstate relay-a
sudo virsh -c qemu:///system setvcpus relay-a 2 --config
sudo virsh -c qemu:///system setmaxmem relay-a 2097152 --config
sudo virsh -c qemu:///system setmem relay-a 2097152 --config
sudo virsh -c qemu:///system domblklist relay-a
# Only after shutdown and a verified backup, resize the identified owned qcow2:
sudo qemu-img resize /var/lib/libvirt/images/ascend-lab/relay-a.qcow2 16G
sudo virsh -c qemu:///system start relay-a
# GUEST: lscpu; free -m; lsblk -f; df -h
# If vda1 is the actual ext4 root layout, use growpart /dev/vda 1 and resize2fs /dev/vda1 in that GUEST.
```
