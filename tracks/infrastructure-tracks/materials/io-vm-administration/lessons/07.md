## How it works

Templates, unique identities, snapshots, image chains, independent backup and restore.

A snapshot may depend on the original disk and storage pool. It is not an independent restore source. A clone needs a unique machine identity, MAC/IP and host keys. A consistent backup must represent a recoverable application state, not just an arbitrary file copy while writes continue. Test the restored guest with the source stopped.

### Operation 1

```sh
# HOST: stop only your owned source; do not continue until domstate is shut off.
sudo virsh -c qemu:///system shutdown relay-a
sudo virsh -c qemu:///system domstate relay-a
mkdir -p work/backups
sudo virsh -c qemu:///system dumpxml relay-a > work/backups/relay-a.xml
sudo qemu-img convert -O qcow2 /var/lib/libvirt/images/ascend-lab/relay-a.qcow2 work/backups/relay-a-cold.qcow2
sudo qemu-img check work/backups/relay-a-cold.qcow2
# RESTORE from the BACKUP into a new disk; the live source disk is not the input.
sudo qemu-img convert -O qcow2 work/backups/relay-a-cold.qcow2 /var/lib/libvirt/images/ascend-lab/relay-restore.qcow2
# Offline guest customization uses libguestfs-tools on the HOST and extra temporary appliance memory.
# The following command modifies the new restore disk only.
sudo virt-customize --add /var/lib/libvirt/images/ascend-lab/relay-restore.qcow2 --hostname relay-restore --run-command 'cloud-init clean --logs --machine-id' --delete '/etc/ssh/ssh_host_*'
ssh-keygen -t ed25519 -f work/vm/relay-restore-key
cp inputs/07/user-data work/vm/restore-user-data
cp inputs/07/meta-data work/vm/restore-meta-data
# Replace the PUBLIC-key placeholder with relay-restore-key.pub in restore-user-data.
cloud-localds work/vm/restore-seed.iso work/vm/restore-user-data work/vm/restore-meta-data
sudo install -m 0644 work/vm/restore-seed.iso /var/lib/libvirt/images/ascend-lab/seed-restore.iso
sudo chown libvirt-qemu:kvm /var/lib/libvirt/images/ascend-lab/relay-restore.qcow2 /var/lib/libvirt/images/ascend-lab/seed-restore.iso
sudo virt-install --connect qemu:///system --name relay-restore --memory 1024 --vcpus 1 --import --disk path=/var/lib/libvirt/images/ascend-lab/relay-restore.qcow2,format=qcow2 --disk path=/var/lib/libvirt/images/ascend-lab/seed-restore.iso,device=cdrom --network network=default --osinfo detect=on,require=off --graphics none --noautoconsole
sudo virsh -c qemu:///system domiflist relay-restore
sudo virsh -c qemu:///system net-dhcp-leases default
# Keep relay-a STOPPED. Verify new MAC, hostname, /etc/machine-id, SSH host-key fingerprint and cloud-init status.
# Start the restored application and compare its actual pre-backup synthetic records.
# A fresh VM without those records or one created from the original disk does not pass recovery.
```
