## How it works

Inventory, lifecycle, resource limits, autostart, failed jobs and console recovery.

Fleet administration requires an inventory and resource accounting, not merely several terminal tabs. A small host can oversubscribe vCPUs but cannot create physical CPU or RAM. Keep headroom for the host and transient work. Failed startup or deletion remains an owned state that needs reconciliation; it must not silently release reservations in a management UI.

## Perform the operation

Predict the outcome, then run one block at a time on the named machine. A foreground server keeps running until you stop it; open the specified second terminal for its client checks. Shell comments describing a different terminal are instructions, not already executed commands.

### Operation 1

```sh
# HOST: observe only your named lab guests.
sudo virsh -c qemu:///system list --all
sudo virsh -c qemu:///system dominfo relay-a
sudo virsh -c qemu:///system domstats relay-a --state --vcpu --balloon --block
sudo virsh -c qemu:///system autostart relay-a
sudo virsh -c qemu:///system shutdown relay-a
sudo virsh -c qemu:///system domstate relay-a
# Retain backups and inventory before final removal; inspect snapshots/storage first.
# virsh undefine removes a definition, not necessarily every disk; do not use bulk remove-all commands.
```
